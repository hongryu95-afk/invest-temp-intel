# invest-temp-intel

[투자온도](https://invest-temp.vercel.app)가 읽는 **미국 지수 5일 방향 예측**을 매일 계산해 두는 곳.
GitHub Actions가 22:00 UTC(= 07:00 KST, 월~금)에 돌고 결과를 `intel.json`에 커밋한다.

앱은 이 파일을 raw로 직접 읽는다:
```
https://raw.githubusercontent.com/hongryu95-afk/invest-temp-intel/main/intel.json
```

## 왜 이것만 떼어 왔나

원래 WSL(`~/us-stock`)에서 매일 17분 30초짜리 파이프라인이 돌며 종목 픽·등급·시장 게이트·지수 예측을 전부 만들었다.
2026-09-19에 **실제로 그날 기록된 예측 99일치**로 채점해보니:

| 부품 | 실측 | 판정 |
|---|---|---|
| 종목 픽 (S&P500 503종목 → 상위 20) | SPY 대비 60거래일 **-4.16%p**, 승률 34% | 근거 없음 |
| 등급 A~F | 99일간 A가 2건, 나머지 1,978건 전부 B | 사실상 상수 |
| 시장 게이트 GO/CAUTION/STOP | **GO 0회**, STOP 12회 중 11회가 NaN 버그 | 죽은 스위치 |
| **지수 5일 방향** | SPY **62.8%** (기준선 54.3%) | 유일하게 기준선 초과 |

기준선을 넘긴 게 이것 하나라 이것만 가져왔다.
그리고 이것도 **아직 "맞다"고 말할 표본이 아니다** — 아래 참조.

전체 리포트: `myClaude/toss_app/invest-temp/진짜성적표_2026-09-19.md`

## 이 숫자를 읽는 법 (중요)

- 5거래일 창이 매일 겹쳐서 **독립 표본은 98개가 아니라 약 19개**다.
- 창이 겹치지 않게 잘라 재면 적중률이 **47~79%**로 흔들린다.
- 명목 n=94로 계산해도 95% 신뢰구간이 **52.7~71.9%**라 기준선 54.3%를 덮는다.
  → **통계적으로는 아직 기준선을 이겼다고 말할 수 없다.**
- 그래서 앱에서도 "참고 지표"로만 쓰고, 개별 종목 매매 신호로 쓰지 않는다.

## 파일

| | |
|---|---|
| `run.py` | 예측 실행 → `intel.json` + `history.csv` |
| `index_predictor.py` | 27피처 GBM (us-stock에서 옮겨 옴, 여기가 원본) |
| `intel.json` | 앱이 읽는 최신 결과 |
| `history.csv` | 예측 기록 누적 (성적표의 미래 재료) |
| `scorecard.json` | 실측 적중률. **자동 갱신 안 됨** — 아래 참조 |

## 정본 규칙

- **앱이 읽는 파일을 쓰는 곳은 여기 하나다.** PC(WSL us-stock)는 `intel.json`을 만들지 않는다.
  (2026-09-19에 `tools/export_intel.py`를 지우고 예약 작업에서 배포 단계를 뺐다.)
- **예측 실패 시 발행하지 않는다.** `run.py`가 exit 1이라 커밋 단계까지 가지 않는다.
  옛 값이 새 값인 척 나가는 게 이 프로젝트에서 제일 비쌌던 사고다(NaN → "전량 매도").
- `intel.json`의 `date`는 실행일, **`asof`가 실제로 쓴 시세의 날짜**다. 앱은 `asof`를 보여준다.

## 성적표 갱신 (수동, 월 1회쯤)

```bash
# WSL에서
cd ~/us-stock && .venv/bin/python scripts/score_live_predictions.py
```
결과 `output/live_scorecard.json`의 `index` 부분을 이 저장소 `scorecard.json`에 옮기고 커밋하면
앱 카드의 적중률 숫자가 같이 바뀐다.

> **과도기 메모**: 지금 성적표는 PC 파이프라인이 남긴 `data.db` 기록(98건)으로 잰 것이다.
> 앞으로 사용자가 보는 예측은 여기서 나오므로, 표본이 쌓이면 **`history.csv` 기준으로 갈아타야 한다.**
> 그때까지 PC 쪽 파이프라인은 기록 연속성 때문에 그대로 둔다.
